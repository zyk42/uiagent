# 一致性评估集设计指南(如何建一个"测得准"的评估集)

> 日期: 2026-10-28 · 依据: 第一轮评估的实证分析(`评估结果-第一轮.md` + 案例拆解)
> 结论先行: **当前 `eval_pc_360.jsonl` 不适合直接用于量化一致性判定**——34% 样本 BF16 自身三次运行都不一致,60% 是坐标型 Tap,导致 L0 被噪声和歧义淹没。本文档给出修正方案。

## 1. 当前评估集的问题(实测数据支撑)

### 1.1 歧义样本占比过高(最大问题)

BF16 同一部署栈、同参数并发重跑 3 次,**只有 237/360(66%)样本三次输出完全一致**。
剩下 123 个样本(34%)连参照模型自己都稳不住,典型形态:

- **多解步骤**: 任务列表里多个子目标都可作为"下一步"(如订票页先点 To 还是先点日期,都是合法操作),模型选哪个都对,但字符串比对必然分歧
- **界面状态歧义**: 列表滚动位置、弹窗/悬停态细微差异导致可选目标不唯一
- **参照本身也会漂**: 这类样本上量化模型一致率仅 17%,但这主要反映"答案空间大",不是量化损伤

→ **这类样本测的是"答案空间大小",不是"模型一致性"。**

### 1.2 动作类型分布失衡

Tap 占 60%,Stop 11.7%,Type 11.4%,其余 10 类动作合计 <18%(Drag/HScroll/Tell 仅 1~3 条)。
后果:

- 整体指标 ≈ Tap 指标,而 Tap 是一致性判定中**对坐标抖动最敏感**的类型
- 尾部动作类型样本量太小(n<5),分层统计完全不可信

### 1.3 坐标噪声淹没 L0

归一化坐标 ±4~6px(约 1080p 屏幕 ±10 物理像素)的抖动在 BF16 自重跑中大量存在。
L0 要求整数坐标完全相等 → 大量"点中同一控件"被判不一致。
(coord 距离中位数 0~4、稳定样本上 fp8 vs BF16 也多为 ±5px 内)

### 1.4 参照答案的正确性未校验

ref = BF16 模型输出,**没有验证它本身对不对**(vs 人工 GT 的匹配率实测仅 7.5%)。
如果参照本身是错的步骤,一致性测的就是"是否一样错"。

## 2. 理想评估集的设计原则

| 原则 | 要求 | 理由 |
|---|---|---|
| **唯一解** | 当前状态下只有一个明显正确的下一步动作 | 消除答案空间噪声,一致率才有意义 |
| **参照正确** | 参照答案经人工或规则验证为正确操作 | 否则测的是"是否一样错" |
| **可复现** | BF16 同栈 N 次重跑 100% 一致(自稳定) | 噪声地板归零,量化差异=净漂移 |
| **类型均衡** | 每个动作类型 ≥30 条(统计显著性下限) | 分层结论可信;Drag/Scroll/Shortcut 等稀有类型要保底 |
| **坐标类与决策类分离** | Tap 类测坐标精度,非 Tap 类测决策正确性,分开报告 | 两类漂移机制不同,混在一起无法归因 |
| **平台均衡** | win/mac/ubuntu 各 1/3 | 校准集覆盖差异的检测 |

## 3. 建议的构建流程(过滤漏斗)

```
候选池(AgentNet 轨迹, 数千条)
  │
  ├─ ① 规则预筛: 剔除多解高发场景(长任务列表中途步、弹窗/悬停态、
  │      滚动后位置不确定的步); 优先取任务首几步(状态确定性强)
  │
  ├─ ② 自稳定性过滤: BF16 同栈并发跑 5 次, 仅保留 5/5 action 规范化后
  │      完全一致的样本(预计淘汰 40~50%)
  │
  ├─ ③ 正确性校验: 保留下来的样本, 参照答案与 AgentNet 人工 GT 核对,
  │      不一致的人工复核(该步骤的标准答案是否唯一); 仍有歧义的剔除
  │
  ├─ ④ 分层配额: 按 动作类型 × 平台 配额采样, 每格 ≥30 条;
  │      Tap 类内部再按"坐标是否容易唯一确定"(按钮中心 vs 空白区)分桶
  │
  └─ ⑤ 终检: 随机抽 5% 人工过一遍, 确认"一个明显正确的动作"
```

目标规模: 每动作类型 ≥30 × 3 平台 ≈ **400~500 条**(与现行 360 相当,但全部为稳定唯一样本)。

## 4. 配套指标调整

新评估集上的报告口径(细则 L0~L3 框架不变):

1. **分开报告两个核心数**:
   - 决策一致率(动词正确,即 L2)= 规划能力保持度 —— 量化损伤的主要告警
   - 坐标距离中位/p90(仅 Tap/Drag 类)= 定位精度保持度 —— 连续指标,不再用 L0 一刀切
2. **L1 取代 L0 作为主指标**(ε=10 吸收标注与栈噪声;L0 仅作参考上限)
3. **噪声地板应接近 100%**: 新集上 BF16 自重跑必须 ≥99%, 否则说明过滤漏斗没拦住歧义样本
4. 保留动词漂移矩阵(L3 的 ref动词→model动词)——这是定位量化损伤模式的最有用视图

## 5. 过渡方案(新集建好之前)

用现行 360 条的 **BF16 自稳定子集**(237 条,三次运行全一致)重新打分:
- 该子集上 fp8 的 L0 = 58.2%(全量上是 47.9%)——数字更能反映真实量化漂移
- 注意子集仍有"参照正确性未校验"的残留问题,结论只作相对比较

打分命令(复用现有工具):
```bash
python3 /root/compare_actions.py <model_details.jsonl> refs_cloudml_bf16_stable237.jsonl
```
(stable237 参照可从 `results/s-20260902173040-8ly5q-n4r7y/details{,_run2,_run3}.jsonl` 三次运行取交集生成)

## 6. 不要做的事

- ❌ 用多解样本测字符串级一致率——测出来的是答案空间不是模型
- ❌ 用 L0(整数坐标完全相等)做选型判据——坐标标注本身有噪声,ε=10 内应视为同一点击
- ❌ 用 BF16 输出当"正确答案"做绝对正确率——它是参照锚点,不是 GT
- ❌ 动作类型不均衡时下分层结论——n<30 的分层数字没有统计意义
