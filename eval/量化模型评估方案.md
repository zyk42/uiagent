# GUI-Owl-1.5-32B 量化模型一致性评估方案

> 更新: 2026-10-21 · 负责人: zhangyikang1
> 评估集说明: 同目录 `README.md` · 量化产物: `../quant/README.md` · 性能压测: `../press/`

## 1. 评估目标

衡量各量化方案相对 **BF16 原版模型的行为漂移程度**,与 `../press/` 的性能数据结合,完成量化方案的最终选型。

评的是**一致性**(量化模型输出 vs BF16 确定性输出),不是任务正确率——任务正确率的绝对水平参考 `gt_action`(AgentNet 人工 GT),但不作为评估基准。

## 3. 评估集

`eval_pc_360.jsonl`(360 条,win/mac/ubuntu 各 120,17 类动作分层覆盖,与所有校准集零重叠),截图在 `images/`。格式与设计详见同目录 `README.md`。

关键字段: `prompt`(完整决策提示词)、`image_path`(截图)、`ref_action` / `ref_thought` / `ref_summary`(BF16 参照输出)、`gt_action`(人工 GT,仅参考)。

## 4. 评估流程

### 4.1 起服务

每个被测模型用 sglang 起 OpenAI 兼容服务(镜像 `micr.cloud.mioffice.cn/sglang-image/ai-arch-llm:3050749-sglang0.5.20-dflash2`,CloudML 上走 cml 部署,5090 单机可直接 `python3 -m sglang.launch_server`),参数与蒸馏 pipeline 一致。

### 4.2 逐条推理

按蒸馏 pipeline 完全相同的请求格式(**不一致则评估无效**):

```python
messages = [
    {"role": "system", "content": "You are a helpful AI PC operating assistant. You need to help me operate the PC to complete the user's instruction."},
    {"role": "user", "content": [
        {"type": "text", "text": record["prompt"]},
        {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{b64_of_image}"}},
    ]},
]
# temperature=0, max_tokens=2048
```

### 4.3 解析与对比

```python
out = response["choices"][0]["message"]["content"]
parsed = json.loads(out.split('```json')[-1].split('```')[0])
# parsed: {"Thought": ..., "Action": ..., "Summary": ...} → 与 ref_* 逐字段对比
```

### 4.4 自检

先跑 BF16 原版: temperature=0 下应与 `ref_*` **100% 一致**。不一致说明管线(prompt/图片/参数/解析)有 bug,修复后再测量化模型。

## 5. 指标

| 指标 | 定义 | 定位 |
|---|---|---|
| **Action 完全一致率** | `model_action == ref_action` 占比 | ★ 核心指标 |
| 动作类型一致率 | 只比动作类型(Tap/Type/Stop/...),忽略参数 | 决策层面漂移 |
| 坐标偏差 | Tap 类坐标归一化欧氏距离中位数 | 定位精度漂移 |
| JSON 可解析率 | 能解析出 Thought/Action/Summary 三字段的比例 | 量化是否破坏输出格式 |
| (参考)vs 人工 GT 匹配率 | `model_action == gt_action` | 量化后的绝对水平 |

按整体 + 分平台(win/mac/ubuntu)+ 分动作类型三个维度统计。

## 7. 选型决策框架

最终选型 = 一致性(本文档)× 性能(`../press/`)× 部署约束(`../quant/README.md`):

1. **一致性一票否决**: Action 完全一致率显著低于 BF16 自一致性水平的方案淘汰。
2. 幸存者中按场景选: 单实例低延迟 → 看 decode/TTFT;批量并发 → 看吞吐;显存受限 → 4bit;H20 现役卡 → 排除 nvfp4;5090/Blackwell → nvfp4 可选。
