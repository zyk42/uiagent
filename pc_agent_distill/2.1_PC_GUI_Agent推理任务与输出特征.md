# 2.1 PC GUI Agent 推理任务与输出特征

> 数据来源：AgentNet（OpenCUA）win/mac + ubuntu 轨迹经 PC-Agent 格式转换后，
> 由 GUI-Owl-1.5-32B-Instruct（sglang, dp=8, temperature=0）蒸馏生成。
> 统计基于 **413,429 条成功解析的推理样本**（win/mac 335,016 + ubuntu 78,413），
> token 计数使用 GUI-Owl-1.5-32B-Instruct 自带 tokenizer，
> 视觉 token 数用模型 processor 对全部 43 种图片尺寸逐一实测。
> 统计脚本：`pc_agent_distill/compute_feature_stats.py`，原始结果：`feature_stats.json`。

---

## 2.1.1 推理任务定义

PC GUI Agent 的单步推理定义为：

```
(当前截图, 任务指令, 文本历史) → 下一步动作
```

具体输入输出（PC-Agent 决策模块形态）：

- **输入**：
  - 当前屏幕截图 1 张（不回传历史截图，见《PC-Agent对话历史构建》）
  - 任务指令（自然语言）
  - 历史操作：前序步骤的 `[Operation 摘要; Action; Reflection]` 文本列表
- **输出**：一个 JSON 对象
  ```json
  {"Thought": "自由文本推理", "Action": "Tap (163, 271)", "Summary": "一句话操作摘要"}
  ```
  其中 Action 是**伪函数调用**——不使用 LLM 的 tool calling 能力，
  而是在 prompt 中定义动作空间（12 个动作），由执行端字符串解析后分发到 pyautogui。

---

## 2.1.2 响应的组成：自由文本 + 动作调用

响应 = JSON 骨架 + 三个字段。字段的 token 占比（30k 随机子样，tokenizer 实测）：

| 字段 | 内容性质 | 平均 token | p99 | 占比 |
|---|---|---|---|---|
| **Thought** | 自由文本（观察+推理） | 79.9 | 153 | **74.3%** |
| **Action** | 函数调用式（结构化） | 10.9 | 31 | **10.1%** |
| **Summary** | 自由文本（一句话） | 16.8 | 43 | **15.6%** |

**关键事实：响应主体是自由文本，不是动作调用。** 动作调用本身只占约 1/10 的 token。
完整响应（含 JSON 骨架与引号）的分布：

| 指标 | mean | p50 | p90 | p95 | p99 | max |
|---|---|---|---|---|---|---|
| 响应 token（API 口径） | 121.7 | 119 | 157 | 171 | 207 | 1275 |
| 响应 token（文本实测） | 120.8 | 118 | 156 | 170 | 206 | 963 |

响应整体较短且分布集中（p99 ≈ 207），但**存在长尾**（max 1275，为长 Thought），
并非"所有响应都很短"。JSON 骨架（`{"Thought": "...", "Action": "...", "Summary": "..."}`
的键名与括号）是固定模板，约 20 个 token 完全可预测。

### 2.1.2.1 输出中的"思考内容"辨析

**模型输出不含独立的思考通道**（实测 100,000 条样本）：

| 检查项 | 结果 |
|---|---|
| 含 `<think>` 标签的输出 | **0 / 100,000** |
| JSON 前有前缀文本的输出 | **0 / 100,000**（全部直接以 `{` 开头） |

- GUI-Owl-1.5 基于 Qwen3-VL，具备 thinking 能力，但本次部署**未开启思考模式**
  （chat template 默认行为 + temperature=0），模型没有产生 `<think>...</think>` 段；
- 推理内容全部由 prompt 约定的 **`Thought` 字段**承载（平均 79.9 token，p99 153），
  即"思考"是输出 JSON 的一个显式字段，而非隐藏通道——这对训练/解析都更友好；
- 轻微格式漂移：极少数样本 Action 参数用单引号（如 `Type (510, 440), ('Scatter Chart')`，
  见示例三），解析端需兼容。

## 2.1.3 动作调用的字段构成

Action 字段的结构为 `动词 (参数)`，各组成部分的 token 量（30k 子样实测均值）：

| 组成部分 | 平均 token | 说明 |
|---|---|---|
| 动词（函数名） | 1.4 | 闭集，见下表 |
| 坐标数字 | 5.8 | 每个坐标值约 2~3 token |
| 引号内文本 | 0.2（全体均值） | 集中在 Type 动作上 |
| 括号/逗号/空格等符号 | ~2 | 固定模板 |

### 动词分布（模型输出，413,429 条全量）

| 动词 | 数量 | 占比 | | 动词 | 数量 | 占比 |
|---|---|---|---|---|---|---|
| Tap | 251,146 | 60.75% | | Right Tap | 10,051 | 2.43% |
| Type | 45,969 | 11.12% | | Scroll | 5,770 | 1.40% |
| Stop | 45,807 | 11.08% | | Drag | 4,164 | 1.01% |
| Double Tap | 17,109 | 4.14% | | 其余（Tell/Triple Tap/…） | ~1,400 | ~0.35% |
| Press | 12,377 | 2.99% | | Shortcut | 11,580 | 2.80% |

- **标准动作动词覆盖率 98.08%**；其余 ~1.9% 为模型把自然语言泄漏进 Action 字段
  （如 "Click on the File menu..."），属于格式噪声。
- 动词分布熵：模型输出 **2.27 bit**，GT **1.84 bit**（模型比 GT 更"爱" Stop/Type，
  GT 里 Scroll/Drag 占比更高）——动词是低熵闭集，预测容易。

### 坐标字段

仅统计带坐标的动作（Tap/Double Tap/Right Tap/Type 等，共 322,261 条）：

| 指标 | x | y |
|---|---|---|
| p50 | 411 | 435 |
| p90 | 804 | 784 |
| p99 | 984 | 965 |
| 唯一值个数 | 1,031 | 1,007 |
| 分布熵 | **9.70 bit** | **9.66 bit** |
| 越界（>999）比例 | \multicolumn{2}{c}{0.041%} |

- 坐标是 [0,999] 归一化整数。唯一值约 1000 个、熵 ~9.7 bit（接近均匀分布的上限
  log2(1000)≈9.97 bit）——**坐标是近似连续的高熵字段，是响应中最难预测的部分**。
- 每个坐标值约占 2~3 个 token，单条动作的坐标参数约 5.8 token。
- 少量越界/畸形坐标（0.041%，如把年份数字误识别为坐标）来自模型的格式错误。

### 按键字段（Press / Shortcut）

按键是**小而集中的闭集**（top 5）：

| 按键 | 次数 | | 快捷键 | 次数 |
|---|---|---|---|---|
| enter | 4,921 | | ctrl+a | 1,702 |
| down | 3,268 | | ctrl+v | 1,484 |
| backspace | 1,758 | | ctrl+c | 956 |
| esc | 303 | | ctrl+s | 579 |

快捷键存在平台变体（`ctrl` vs `command`/`cmd`），且模型偶尔输出未归一化的 `cmd`——
训练或后处理时建议统一。

### 输入文本字段（Type 动作）

| 指标 | mean | p50 | p90 | p99 | max |
|---|---|---|---|---|---|
| 文本长度（字符） | 18.3 | 8 | 31 | 231 | 1,761 |

以短输入为主（搜索词、文件名、单元格公式），长尾为文档段落/代码。
这是 Action 里**唯一的开放词表字段**，内容不可枚举。

## 2.1.4 输入长度、视觉 token、历史长度分布

### 输入总长度（文本 + 视觉 token）

| 指标 | mean | p50 | p90 | p95 | p99 | max |
|---|---|---|---|---|---|---|
| 输入总 token | 4,236 | 3,748 | 6,572 | 7,924 | 11,397 | 27,060 |
| 其中：prompt 文本 | 3,058 | 2,641 | 5,308 | 6,609 | 10,200 | 26,180 |
| 其中：视觉 token（实测） | 1,177 | 888 | 2,040 | 2,040 | 3,600 | 9,000 |

### 视觉 token 数

- 全部图片仅 **43 种尺寸**（AgentNet 录制分辨率有限集合），视觉 token 数也随之离散化
- 视觉 token 由 Qwen3-VL processor 实测（patch 16 × merge 2，即 32px/token 网格，
  再经 smart resize）：主流档位为 **888 / 2040** 两档，最大 9,000
- 视觉 token 占输入的 ~28%（1177/4236），且**同一尺寸的图片 token 数完全相同**——
  对 KV cache 复用和批处理打包很友好

### 历史长度（### History operations ### 的条数）

| 指标 | mean | p50 | p90 | p95 | p99 | max |
|---|---|---|---|---|---|---|
| 历史步数 | 11.4 | 9 | 23 | 30 | 50 | 137 |

历史长度随轨迹推进线性增长（PC-Agent 默认每个子任务清空一次，单轨迹最长 137 步），
是 prompt 文本长度的主要变量来源——文本 token 与历史步数近似线性相关。

## 2.1.5 预测特点总结（对推理加速的启示）

| 字段 | 预测难度 | 依据 |
|---|---|---|
| JSON 骨架 | **极低**（完全可预测） | 固定模板，~20 token 零信息量 |
| Thought/Summary | 中（自由文本，但与画面/历史强相关） | 占 token 大头（74%），平均 97 token |
| 动作动词 | **低**（闭集，熵 2.3 bit） | 12 个标准动词覆盖 98% |
| 按键/快捷键 | **低**（小闭集） | top-3 按键占 Press 的 ~57% |
| 坐标 | **高**（近连续，熵 9.7 bit/值） | 但每动作仅 ~6 token |
| Type 文本 | 高（开放词表） | 出现频率 11%，长度长尾 |

对投机解码/输出加速的直接启示：
1. 响应短（p99≈207 token）但结构高度规整——**JSON 骨架、字段名、动作动词、括号模板
   都是高可预测 token**，适合作为投机解码的"白送"段；
2. **坐标 token 是最难投机的部分**，但它们占比小（每响应约 6 token），
   是验证草稿的主要瓶颈点；
3. 输入端长（平均 4.2k token，p99 11.4k）而输出端短，**prefill 占主导**——
   输入侧优化（前缀缓存复用 prompt 模板与动作空间定义部分、同尺寸图片的
   vision token 批处理）收益大于输出侧；
4. prompt 中动作空间定义 + system prompt 是完全固定的前缀（约 1.5k token），
   蒸馏/推理时前缀缓存命中率极高（实测 sglang 日志中 cached-token 占比可观）。

## 2.1.6 完整输入输出示例

以下示例为实际蒸馏请求的真实记录（输入 = system prompt + user[prompt 文本 + 截图]，
此处略去截图二进制，只示文本部分；输出 = 模型原始返回）。

system prompt（所有请求固定相同）：

```
You are a helpful AI PC operating assistant. You need to help me operate the PC to complete the user's instruction.
```

### 示例一：轨迹首步（无历史，最简形态）

**输入 prompt：**

```
### Background ###
This image is a computer screenshot where icons are marked with numbers. Its width is 1280 pixels and its height is 720 pixels. The user's instruction is: Use Excel Formula NORM to sample 30 point from Standard normal distribution.

### Task requirements ###
In order to meet the user's requirements, you need to select one of the following operations to operate on the current screen:
Note: Since no extracted information is provided, you need to directly analyze the screenshot and output normalized coordinates.
For Tap actions, use normalized coordinates where x and y are in the range [0, 999], with (0, 0) at the top-left corner and (999, 999) at the bottom-right corner.
For certain items that require selection, such as font and font size, direct input is more efficient than scrolling through choices.
You must choose one of the actions below:
Right Tap (x, y): Right tap the position (x, y) in current page. This can be used to create a new file.
Tap (x, y): Tap the position (x, y) in current page. This can be used to select an item.
Double Tap (x, y): Double tap the position (x, y) in the current page. This can be used to open a file. If Tap (x, y) in the last step doesn't work, you can try double tap the position (x, y) in the current page.
Shortcut (key1, key2): There are several shortcuts (key1+key2) you may use. ...
Press (key name): There are several keys that may help. ...
Type (x, y), (text): Tap the position (x, y) and type the "text" in the input box and press the enter key. ...
Select (content): Select the referred 'content' in the current document ...
Replace (x, y), (text): Replace the editable content in (x, y) with the "text". ...
Append (x, y), (text): Append the "text" content after the content at (x, y) location. ...
Tell (answer): Tell me the answer of the input query.
Stop: ONLY use this action when you can VERIFY from the CURRENT SCREENSHOT that ALL requirements in the user's instruction have been ACTUALLY COMPLETED. ...

### Output format ###
You should output in the following json format:
{"Thought": "This is your thinking about how to proceed the next operation, please output the thoughts about the history operations explicitly.", "Action": "Tap () or Double Tap () or Triple Tap () or Shortcut () or Press() or Type () or Tell () or Stop. Only one action can be output at one time.", "Summary": "This is a one sentence summary of this operation."}
```

**模型输出：**

```json
{"Thought": "To generate 30 random points from a standard normal distribution using the NORM function in Excel, I need to first select cell A2 as the starting point for entering the formula. This aligns with the task of sampling data points systematically.", "Action": "Tap (42, 290)", "Summary": "Selected cell A2 as the starting point for entering the NORM formula."}
```

### 示例二：带历史的中段步（Excel 条件格式任务，第 6 步）

**输入 prompt（`### Task requirements ###` 与 `### Output format ###` 为固定段落，与示例一完全相同，此处省略；截图略）：**

```
### Background ###
This image is a computer screenshot where icons are marked with numbers. Its width is 1280 pixels and its height is 720 pixels. The user's instruction is: Change the data in columns A, B, and C of the current Excel sheet (excluding the headers) to orange data bars, then create a scatter plot from these columns, naming the title "Scatter Chart," and place it to the right of the table.

### History operations ###
Before arriving at the current screenshot, you have completed the following operations:
Step-1: [Operation: Click on cell A2, which is the first data cell in column A below the header "数学分析A".; Action: Tap (25, 245); Reflection: ...cell A2 is now selected as indicated by the highlighted cell border...]
Step-2: [Operation: Click on the "Conditional Formatting" button in the Home tab's Styles section of the ribbon.; Action: Tap (517, 112); Reflection: ...]
Step-3: [Operation: Click on the orange gradient data bar option in the Data Bars submenu.; Action: Tap (593, 285); Reflection: ...]
Step-4: [Operation: Click on the "View" tab in the Excel ribbon; Action: Tap (293, 42); Reflection: ...clicking on the View tab is unnecessary for the task at hand... therefore both incorrect and redundant.]
Step-5: [Operation: Click on the Insert tab in the Excel ribbon; Action: Tap (115, 43); Reflection: ...The Insert tab contains all the chart creation options needed...]

### Task requirements ###   （固定动作空间定义，同示例一）
### Output format ###       （固定输出格式，同示例一）
```

注意 Step-4 的 Reflection 包含了**纠错信息**（"incorrect and redundant"），模型可据此避免重蹈。

**模型输出：**

```json
{"Thought": "The user has successfully applied orange data bars to columns A, B, and C (excluding headers) as required. Now, the next step is to create a scatter plot from these columns. To do this, I need to select the data range in columns A, B, and C, then navigate to the Insert tab to access chart creation tools. The current screenshot shows that the Insert tab is already active, so I should proceed with selecting the data range for the scatter plot.", "Action": "Tap (130, 212)", "Summary": "The user clicked on cell A2 to begin selecting the data range for creating a scatter plot."}
```

### 示例三：Type 动作（含输入文本，同任务第 8 步）

**输入 prompt**：同示例二的结构（历史 7 步，略）。

**模型输出：**

```json
{"Thought": "The scatter chart has been successfully created and placed to the right of the data table. The next step is to rename the chart title from 'Chart Title' to 'Scatter Chart' as specified in the task requirements. I need to click on the chart title text box to edit it and change the title accordingly.", "Action": "Type (510, 440), ('Scatter Chart')",
 "Summary": "Click on the chart title text box to begin editing it."}
```

可观察到：
- Thought 引用了历史（图表已创建）并规划下一步——思考内容承载于 Thought 字段；
- 该样本 Action 参数用了单引号 `('Scatter Chart')`（规范为双引号），属轻微格式漂移；
- Summary 与 Thought 语义有轻微不一致（Thought 说要改名，Summary 只说点击）——蒸馏数据的固有噪声。
